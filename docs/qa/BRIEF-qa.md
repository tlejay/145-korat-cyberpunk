## ตอนนี้ (ยังไม่มีโค้ดเกม — มีแค่บรีฟ research)
1. เขียน `docs/qa/TEST-PLAN.md` — test case ครบทุกด้าน แต่ละข้อมี ID (เช่น `PERF-01`), ขั้นตอน, เกณฑ์ผ่านที่วัดได้ (ตัวเลข ไม่ใช่ "ลื่นดี"), ระดับ (🔴 ห้ามขึ้นถ้าไม่ผ่าน / 🟡 ควรแก้ / 🟢 nice to have), วิธีทดสอบ (อัตโนมัติ / มือ / มือถือจริง):
   - **ความสนุก/ความรู้สึกขับ (game feel):** ตอบสนองปุ่มภายในกี่ ms, ดริฟต์ควบคุมได้, กล้องท้ายรถไม่วูบวาบ/ไม่ทะลุตึก, ชนแล้วไม่ติดค้าง, ไม่ตกขอบโลก, กระโดด + ออกตัวเร็วรู้สึกเหมือนรถจริงตาม `research/car/`
   - **มือถือ:** แนวนอน, ปุ่มสัมผัสขนาด ≥ 48px ไม่บังวิว, multi-touch (เร่ง+เลี้ยวพร้อมกัน), iOS Safari + Android Chrome, notch/safe-area, เสียง unlock บน iOS, แบตร้อน/throttle
   - **ประสิทธิภาพ:** fps (เป้า 60, ห้ามต่ำกว่า 30 บนมือถือกลาง ๆ), เวลาโหลดแรกบน 4G, ขนาด bundle + asset, draw calls, หน่วยความจำ, ไม่มี memory leak หลังเล่น 10 รอบ
   - **ความสมจริง:** ลำดับถนน/ทางแยก/คูเมือง/ตำแหน่งอนุสาวรีย์ตรงกับ `research/osm/` + `research/streetview/` · ชื่อถนนไทยถูก · ความเคารพย่าโม (ชนอนุสาวรีย์ไม่ได้ ไม่มีอะไรล้อเลียน)
   - **ภาพ/เสียง:** นีออน bloom ไม่แสบตาจนอ่าน HUD ไม่ออก, ไม่มีตัวอักษรมั่วจาก imagegen, เสียงมอเตอร์ไล่ pitch เนียน, loop BGM ไร้รอยต่อ, ปุ่มปิดเสียง
   - **UI/ภาษา + Error:** ไทยทั้งหมด ไม่มีอังกฤษหลุด, กรณี error ตามหัวข้อ 9 ของ CLAUDE.md ครบ, ไม่มี `alert()`
   - **License/ลิขสิทธิ์:** ทุก asset ใน `public/` อยู่ใน `research/CREDITS.md`, ไม่มีภาพจาก Google/ภาพข่าวในเกม, หน้าเครดิตมี OSM
   - **Deploy:** URL ตอบ 200, ไม่มี console error, cache header asset
2. เลือกเครื่องมือทดสอบอัตโนมัติ (แนะนำ Playwright + device emulation แนวนอน, วัด fps ผ่าน `requestAnimationFrame` hook / hook debug ในเกม) — เขียนเป็นข้อกำหนดให้ dev pane ทำ "test hook" ที่เกมต้องมี เช่น `window.__game.stats()` คืน fps / ตำแหน่งรถ / สถานะ — ใส่ใน `docs/qa/TEST-HOOKS.md`
3. เขียน `docs/qa/RELEASE-GATE.md` — checklist สั้นที่ต้องผ่านทุกครั้งก่อน `vercel deploy --prod` และรูปแบบรายงานผล (`docs/qa/reports/YYYY-MM-DD-<build>.md`)
4. ทบทวนบรีฟ research ทุกตัว ถ้าเห็นช่องว่างที่จะทำให้เกม "ห่วย" (เช่นไม่มีใครดูเรื่องกล้อง/การควบคุม) ให้ลิสต์ไว้ท้าย TEST-PLAN หัวข้อ "ความเสี่ยงที่ conductor ควรรู้"

## ข้อห้าม
ห้าม commit / push / deploy · ห้ามแก้โค้ดเกมเอง (QA หาบั๊ก ไม่ใช่แก้) · เสร็จแล้วเขียนสรุป ≤ 15 บรรทัดบนสุดของ TEST-PLAN แล้วจบ turn
