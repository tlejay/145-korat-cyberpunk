### 2.2 กติกาที่เกมกำหนด (ฟิสิกส์ต้องเคารพ)

- **ข้ามสิ่งกีดขวางด้วยการกระโดดไม่ได้** — แบริเออร์นีออนตามแยก ตึก ขอบลาน = สูงไม่จำกัดสำหรับรถ (กันตัดทาง) · **ยกเว้น** จุดทางลัดข้ามคูที่ออกแบบไว้ (§3.1) ที่แนวราวริมคูต่ำพอให้ข้าม
- ดริฟต์เข้าด้วย **แตะเบรกขณะเลี้ยว** (|steer| ≥ 0.5 ที่ความเร็ว ≥ ~50 กม./ชม.) · ออกด้วยการปล่อยเลี้ยว · ตั้งค่า "ดริฟต์อัตโนมัติ" (ปิดเป็นค่าเริ่มต้น) = เลี้ยวเต็มค้าง ≥ 0.25 วิ ที่ความเร็วสูงเข้าดริฟต์เอง
- "นับเป็นดริฟต์" (สำหรับแต้ม/เติมถัง) เมื่อ slip ≥ 15° และความเร็ว ≥ 50 กม./ชม. · ชนระหว่างดริฟต์ = ก้อนนั้นหลุด
- `stuckMs` > 2,000 → ปุ่ม "กลับเข้าเส้นทาง" · > 3,000 → กลับเองอัตโนมัติ (FEEL-13)
- ชนขอบลานย่าโม (`objectKind = 'monument'`): **ไม่มีประกายไฟ ไม่มีเสียงชนแรง ไม่สั่นจอ/เครื่อง** แค่เด้งนุ่ม (landmarks §5 ข้อ 2)
- physics step คงที่ + render interpolate · `qa.fixedStep` ต้อง deterministic (ใช้ replay ghost ตรวจแต้มในอนาคต §6.3)

### 2.3 Respawn (กลับเข้าเส้นทาง)

| เงื่อนไข | ทำอะไร |
|---|---|
| คว่ำ (แกน up ของรถ y < 0.3) นาน 1.0 วิ · `stuckMs` > 3,000 | อัตโนมัติ |
| **ตกคูเมือง** / ตกขอบ / ออกนอก `boundsM` | อัตโนมัติทันทีที่น้ำท่วมล้อ (ไม่ให้เห็นรถจมนาน) |
| ขับย้อนทาง > 5 วิ | ข้อความ "ผิดทาง" + ปุ่มกลับเข้าเส้นทาง (ไม่บังคับ) |
| ผู้เล่นกดเอง (pause / R / ปุ่มที่โผล่หลังติด 2 วิ) | ได้เสมอ |

### 2.5 เขตลานย่าโม + ประตูชุมพล (บังคับ — CLAUDE.md §1, REAL-12/13)

## 3. 4 จุดโชว์ (Tle เลือก 2026-10-17) — ฝั่งเกม

> PHYSICS.md คำนวณ "ทำได้จริงไหม เท่าไร" · ส่วนนี้คือ "ผู้เล่นรู้ได้ยังไง ทำยังไง ได้อะไร เห็นอะไร"

### 3.1 กระโดดข้ามคูเมือง — ทางลัดเสี่ยงได้เสี่ยงเสีย

- **ตำแหน่ง**: PHYSICS.md เลือกจุดบนสนาม A ที่คูกว้าง 23–40 ม. และเป็นทางลัดจริง ห่างเขตลานย่าโม · เกมรับค่า `shortcut.takeoff` / `shortcut.landing` (โพลิกอน 2 ฝั่ง) จาก `public/data/`
- **ผู้เล่นรู้ได้ยังไง**: ลูกศรนีออนบนพื้นชี้เข้าหาริมคู 150 ม. ก่อนถึง + ราวริมคูช่วงนั้นเป็นไฟกะพริบช้า (≤ 1 ครั้ง/วิ, VIS-04) แทนรั้วทึบ · ครั้งแรกของการแข่งมีข้อความ "ทางลัด: กระโดดข้ามคู" · ทั้งหมดไม่ใช่คำบังคับ — ทางปกติยังวิ่งได้
- **ตัวช่วยตัดสินใจ** (สำคัญมากบนมือถือ): ช่วง 150 ม. ก่อนจุดกระโดด เกจถังลมขึ้นขีด "พอข้ามคู" · ไอคอนกระโดดบนปุ่มเปลี่ยนเป็นสีเขียวเมื่อ **ความเร็ว + แก๊ส + ตำแหน่ง** พอข้าม (ใช้ฟังก์ชันทำนายจุดตกตัวเดียวกับ §2.5) · สีส้ม = ไปไม่ถึง
- **ทำยังไง**: กดกระโดดในโซน takeoff → กดค้าง = ประคองลอย/ยืดระยะ (กินแก๊สต่อ) · ปล่อยเร็ว = ตกเร็ว
- **ได้อะไร**: เร็วกว่าทางปกติ (เป้า 3–5 วิ ต่อรอบ — ยืนยันใน PHYSICS.md) + แต้ม "ข้ามคู +500" (นับในสไตล์ §6) · **ตก = respawn ฝั่งเดิม เสียเวลามากกว่าที่จะได้** (เป้า เสีย ≥ 4 วิ) — ต้องเป็นเดิมพันจริง
- **กล้อง** (§4): ตอนลอยเหนือคู กล้องยกสูง +1.5 ม. ถอยห่าง +1 ม. ก้มลง 8° ให้เห็นน้ำใต้รถ + ฝั่งที่จะลง · slow-motion **ไม่ใช้** (มือถือแข่งเวลา) · ลงพื้นสั่นตามแรง
- **checkpoint**: ทางลัดเป็น "เส้นทางเลือก" — checkpoint ช่วงที่ถูกข้ามรวมเป็นกลุ่ม: ผ่านกลุ่มปกติ **หรือ** ผ่านเส้น landing ฝั่งตรงข้าม อย่างใดอย่างหนึ่ง = ไม่นับ missed (§5.2)
- ghost: บันทึกการข้ามคูด้วย (ผู้เล่นเห็น ghost ตัวเองบินข้าม = ชวนลอง)

### 3.2 ออกตัว 4.6g — launch control

- **ตอนเริ่มแข่ง** (ทุกครั้ง): ระหว่างนับ 3-2-1 **กดค้าง BOOST** = "เตรียมออกตัว" → พัดลมดูดท้ายหมุนเรืองแสง + เสียงหวีดไต่ระดับ + รถยุบหน้าลงเล็กน้อย + เกจ g ขึ้นกลางล่าง
  - **ปล่อย BOOST ตอน "ไป!"** (หน้าต่าง ±0.15 วิ) → "ออกตัวสมบูรณ์" 4.6g (ค่าใน PHYSICS.md) · ไม่กินแก๊ส
  - ปล่อยเร็วกว่า "ไป!" → ล้อฟรีหมุน 0.5 วิ (เสียเปรียบเล็กน้อย ไม่ปรับแพ้) · ปล่อยช้า (≤ 0.5 วิ) → แรงลดตามความช้า · ไม่กดเลย = ออกตัวปกติ (ด้วยปุ่มเร่ง)
  - ข้อความผล 1 วิ: "ออกตัวสมบูรณ์ 4.6g" / "ล้อฟรี" / "ช้าไป" + แต้มสไตล์ launch สมบูรณ์ +300
- **กลางการแข่ง**: จอดนิ่ง (< 5 กม./ชม. เช่นหลังชน/หลัง respawn ไม่นับ) กดค้าง BOOST ≥ 0.4 วิ แล้วปล่อย = launch เหมือนกัน แต่ **กินแก๊ส** (PHYSICS.md) · มือใหม่กด BOOST ค้างไว้เฉย ๆ ก็พุ่งได้ (ปล่อยเมื่อไหร่ก็พุ่ง) — ไม่มีวิธีผิด
- **feedback ≥ 3 อย่าง** (FEEL-03 ต้อง ≥ 2): FOV กระชาก (§4) · กล้องสั่นตาม g · เกจ g ตัวเลขสด · ไอขาว 4 ลำจาก diffuser (ไม่มีไฟ — cold gas) · haptic (Android)
- **สอนเล่น**: หน้าสอนเล่นมีข้อ "กดค้างสายฟ้าตอนนับถอยหลัง แล้วปล่อยตอน 'ไป!'" · รอบแรกของผู้เล่นใหม่ขึ้นคำใบ้บนปุ่ม BOOST ระหว่างนับถอยหลัง

### 3.3 ดริฟต์โค้งกลับ 148° — ไฮไลต์ประจำรอบ

- **ที่**: หัว ถ.ราชดำเนิน → ถ.มิตรภาพ (~550 ม. จากเส้นชัย, ต่อจากโค้งซ้าย 53° ที่ ~520 ม.) · อยู่นอกเขตลานย่าโม (~570 ม. ทางเหนือ)
- **ผู้เล่นรู้ได้ยังไง**: ลูกศรตัว U ขึ้นล่วงหน้า 3 วิ (มากกว่าโค้งปกติ 2.5 วิ) · แบริเออร์นีออนด้านนอกโค้งเป็นแถบ chevron ไล่สีตามทิศ · ป้ายเบรก 100/50 ม. ข้างทาง (ไม่มีตัวอักษรจาก imagegen — ใช้ฟอนต์จริง)
- **ทำยังไง**: เบรก + เลี้ยวขวา (แตะเบรก = เข้าดริฟต์) → กดเลี้ยวค้าง + เร่ง = ดริฟต์ค้างทั้งโค้ง (F4) · countersteer assist (PHYSICS.md) กันหมุนเกินสำหรับปุ่มดิจิทัล
- **ป้ายวัดดริฟต์** (`hud-drift`): ระหว่างดริฟต์ที่โค้งนี้ แสดง "มุม 38° · 42 ม." ใต้ combo · จบโค้งขึ้นผล "ดริฟต์โค้งกลับ 46 ม. +620" · จำสถิติ "ดริฟต์โค้งกลับยาวสุด" ของตัวเองในหน้าสรุป
- **ได้อะไร**: เร็วกว่าเกาะถนน (F3) + เติมแก๊ส 10/วิ ตลอดโค้ง (พอ BOOST ออกสู่ ถ.มิตรภาพ) + แต้มดริฟต์ปกติ — **ไม่มีโบนัสพิเศษเพิ่ม** นอกจากป้ายสถิติ (กันแต้มเฟ้อที่โค้งเดียว)
- **กล้อง** (§4): ระหว่างดริฟต์โค้งนี้ เพิ่มการหันตามทิศความเร็วเป็น 0.5 + ถอยห่าง +0.5 ม. ให้เห็นวงโค้ง/ควันยาง

### 3.4 ฝน + สายไฟ/โคม/ป้ายแกว่ง — บรรยากาศ

- **ฝน**: เปิดตลอด (กลางคืน cyberpunk) · ความแรง 3 ระดับตาม quality tier (low = ไม่มีฝนตกเป็นเส้น เหลือแค่ถนนเงาเปียก) · ผลต่อการขับตาม F9 (μ เปียก/แอ่งน้ำใน PHYSICS.md) · **ทุก quality tier ใช้ μ เดียวกัน** (ไม่งั้นแต้มไม่ยุติธรรม — ภาพต่างได้ ฟิสิกส์ต้องเท่ากัน)
- แอ่งน้ำ: เห็นชัด (สะท้อนนีออน) วางตามจุดที่ PHYSICS.md/Street View กำหนด · ลุยแล้วน้ำกระจาย + เสียงซ่า + ท้ายส่ายเล็กน้อย · ไม่ใช่กับดักที่มองไม่เห็น
- **สายไฟ/โคมจีน/ป้ายแขวน**: ภาพล้วน — **ไม่ชนรถ ไม่ชนกล้อง** (ไม่อยู่ในชุด collider/spherecast) · แกว่งตามลมจากรถวิ่งผ่าน + ไอพ่น BOOST/กระโดด (Verlet ใน PHYSICS.md) · รถกระโดดทะลุสายไฟได้โดยสายสะบัด (ไม่ขาด ไม่มีประกายไฟฟ้า — ไม่ทำให้ดูเป็นอันตราย)
- ไม่มีเสียงฟ้าร้อง/ฟ้าแลบกะพริบ (VIS-04) · ฝนมีเสียงพื้นหลังเบา ๆ ลดเสียงลงเมื่อ BOOST
- ตั้งค่า "ลดเอฟเฟกต์" = ปิดสายไฟแกว่ง (ประหยัดแบต) ฝนเหลือขั้น low

### 6.2 Pseudo-code → `src/net/score.ts` (ใช้ร่วม client/server)

```ts
// Shared by client (result-screen preview) and server (authoritative).
// minLapMs and cpMinMs come from scripts/physics-sim.mjs (see docs/dev/PHYSICS.md) — regenerate when physics changes.
export const TRACK_RULES: Record<string, {
  laps: number; parLapMs: number; minLapMs: number; checkpoints: number;
  cpMinMs: number[];               // min possible time between consecutive checkpoints (index = checkpoint)
  altGroup: [number, number] | null; // checkpoints skippable by the moat shortcut [first, last]
}> = {
  A: { laps: 1, parLapMs: 78_000, minLapMs: 45_000 /* placeholder */, checkpoints: 34, cpMinMs: [], altGroup: null /* from PHYSICS.md */ },
};

export const SCORE = {
  timeBase: 100_000,     // score at exactly par
  driftPerSec: 120, driftChain: 150,
  shortcut: 500, cleanLanding: 250, perfectLaunch: 300, cleanLap: 3_000,
  respawnPenalty: 2_000,
  styleCapRatio: 0.20,
};

export function computeScore(r: RunResult) {
  const rule = TRACK_RULES[r.trackId];
  const parTotal = rule.parLapMs * rule.laps;
  const time = Math.round(SCORE.timeBase * (parTotal / r.totalMs) ** 2);  // squared: top-end gains matter more
  const styleRaw =
    Math.round((r.driftMs / 1000) * SCORE.driftPerSec) + r.driftChains * SCORE.driftChain +
    r.shortcuts * SCORE.shortcut + r.cleanLandings * SCORE.cleanLanding +
    r.launches.perfect * SCORE.perfectLaunch + r.cleanLaps * SCORE.cleanLap;
  const style = Math.min(styleRaw, Math.round(time * SCORE.styleCapRatio));
  const respawn = -r.respawns * SCORE.respawnPenalty;
  return { time, styleRaw, style, respawn, total: Math.max(0, time + style + respawn) };
}

// Server-side plausibility. Returns an error code (mapped to Thai in src/net/messages.ts) or null.
export function validateRun(r: RunResult, t: { startedAtMs: number; nowMs: number; trackId: string }): string | null {
  const rule = TRACK_RULES[r.trackId];
  if (!rule || r.trackId !== t.trackId) return 'BAD_TRACK';                         // 1 token bound to track
  if (r.laps !== rule.laps || r.lapMs.length !== rule.laps) return 'BAD_LAPS';       // 2
  if (Math.abs(sum(r.lapMs) - r.totalMs) > 50) return 'BAD_TOTAL';                   // 3
  if (r.lapMs.some(ms => ms < rule.minLapMs)) return 'TOO_FAST';                     // 4 physical floor
  const elapsed = t.nowMs - t.startedAtMs;                                           // 5 server wall clock
  if (elapsed < r.totalMs - 500 || elapsed > r.totalMs + 30 * 60_000) return 'BAD_CLOCK';
  if (r.splitsMs.length !== rule.checkpoints * rule.laps) return 'BAD_SPLITS';       // 6 splits vs sim minimum
  for (let i = 0, prev = 0; i < r.splitsMs.length; prev = r.splitsMs[i++]) {
    const cp = i % rule.checkpoints, dt = r.splitsMs[i] - prev;
    const inAlt = rule.altGroup && cp > rule.altGroup[0] && cp <= rule.altGroup[1];
    if (inAlt ? dt < 0 : dt < rule.cpMinMs[cp]) return 'BAD_SPLITS';                 // alt group may repeat (dt = 0)
  }
  if (r.shortcuts > rule.laps || r.cleanLaps > rule.laps || r.refills > rule.laps) return 'BAD_STYLE';  // 7
  if (r.cleanLandings > r.jumps || r.launches.perfect > r.launches.total || r.driftMs > r.totalMs * 0.7) return 'BAD_STYLE';
  if (!gasBudgetOk(r)) return 'BAD_TANK';   // 8 usage ≤ start + regen·t + drift regen + landings + refills (costs from PHYSICS.md)
  if (!ACCEPTED_BUILDS.includes(r.build)) return 'OLD_BUILD';                        // 9
  return null;
}
```

ตัวอย่าง (สนาม A 1 รอบ, par 78 วิ): เวลา 70 วิ → time = 100,000 × (78/70)² = **124,163** · ดริฟต์ 20 วิ 6 ก้อน = 3,300 · ข้ามคู 1 = 500 · ลงสวย 2 = 500 · launch สมบูรณ์ = 300 · ข้ามด่าน 2 = 600 · ไม่ชน = 3,000 → style 8,200 (เพดาน 24,833) → **132,363**

> **ข้ามด่าน (fix #11, conductor 21:18):** `checkpointClears × 300` รวมในโบนัสสไตล์ (เพดาน 20% เดิม ไม่มีคอลัมน์ใหม่) · server เชื่อเฉพาะด่านที่ ghost ของรอบนั้นมีจุด `airborne` ≥ 2 จุดภายใน 14 ม. จากพิกัดด่าน (`SITES` ใน src/checkpoint/sim.ts) · ไม่ส่ง ghost = ไม่ได้แต้มข้ามด่าน · ghost ผูก `TRACK_VERSION` (sha256 ของ track-A.json) — ghost สนามเวอร์ชันอื่นไม่ถูกเล่น
