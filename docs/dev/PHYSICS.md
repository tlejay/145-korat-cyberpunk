## 1. แกนกลาง

### 1.1 เวลาและลำดับต่อ step

- **fixed timestep 120 Hz** (dt = 8.33 ms) ใช้ accumulator สูงสุด 8 step ต่อเฟรม (ตรงกับ GAMEPLAY §2.1) · เรนเดอร์ interpolate ระหว่าง step · `qa.fixedStep` ใช้เส้นทางเดียวกัน
- ยางกับแรงในแนวราบไม่ต้องแบ่ง substep เพิ่ม เพราะ Pacejka ที่ 120 Hz นิ่งเมื่อ v > 3 ม./วิ · ต่ำกว่า 3 ม./วิ ให้ผสมไปเป็นโมเดล kinematic (§1.3 ข้อ 5)
- สายไฟ โคม และป้าย **จำลองที่ 60 Hz ครั้งเดียวต่อเฟรมเรนเดอร์** แยกจากรถ (ภาพล้วน ไม่ย้อนมาออกแรงกับรถ)
- ลำดับต่อ step: input → แรงขับ/เบรก/หัวพ่น → ยาง (slip angle, friction ellipse) → integrate แนวราบ (vx, vy, r) → raycast ช่วงล่าง (y, pitch, roll, การแตะพื้น) → ชนเส้น 2D (depenetrate + impulse) → ถังลม/สถานะ → อัปเดต hook
- **ห้าม allocate ใน step** ให้ใช้ Float32Array / object เดิมซ้ำ (PERF-14)

### 1.2 พิกัด

- โลก three.js: x = ตะวันออก · y = ขึ้น · **z = ใต้** (`z = −y_OSM`) · จุด (0,0) = อนุสาวรีย์ (TEST-HOOKS §1 ข้อ 4)
- ตัวรถ: x หน้า · y ซ้าย · ค่า slip angle β เป็นบวกเมื่อท้ายปัดออก
- **g สองค่า:** แรงยาง น้ำหนักกดล้อ และเลข g ทุกตัวบน HUD/hook ใช้ **9.81** · แรงโน้มถ่วงตอนรถลอยใช้ **12** (GAMEPLAY) เพื่อให้กระโดดกระชับบนจอเล็ก · แยกสองค่านี้ทำให้กระโดดดูหนักแน่น โดยไม่เพิ่มแรงยึดถนน

### 1.6 การชน — แบริเออร์ ตึก ราวเตี้ย

- ใช้เส้น 2D และกฎของ GAMEPLAY §2.5 ทั้งหมด (ดันออก + เผื่อ 2 ซม. · เฉียดเหลือความเร็ว 85% · ชนตรงเหลือ 30% · restitution 0.2–0.25 · ขอบลานย่าโม 0.1 แบบนุ่ม)
- ในรูป impulse: `J_n = −(1+e)·m·v_n` · แรงเสียดทานตามแนวกำแพง `J_t ≤ μ_w·|J_n|` กับ μ_w = 0.3 แล้ว clamp ให้ความเร็วตามแนวกำแพงไม่เกิน 85% (เฉียด) · ชนแล้วไม่ยกแกน y · ความเร็วหลังชน ≤ ก่อนชนเสมอ (FEEL-14)
- **เพิ่มจาก GAMEPLAY: เส้นชนมีความสูง `h`** — ชนเฉพาะเมื่อใต้ท้องรถต่ำกว่า h (`pos.y + 0.11 < h`)

  - **ราวลูกกรงริมคู และแบริเออร์ปากถนนพลแสนฝั่งตะวันตก: `h = 1.0 ม.`** เพื่อให้กระโดดข้ามคูได้ (§2) — ถ้าไม่มีกฎนี้กระโดดข้ามคูไม่ได้เลย

## 3. โชว์ 2 — ออกตัว 4.6 g

### 3.1 ทำไมยางอย่างเดียวไม่พอ (พิสูจน์)

0–60 mph ใน 0.59 วิ → a เฉลี่ย = 26.82 / 0.59 = **45.5 ม./วิ² = 4.64 g**

| ชุด | g สูงสุด | 0–60 mph | 0–100 | น้ำหนักล้อหน้าต่ำสุด |
|---|---|---|---|---|
| ยาง μ 1.1 อย่างเดียว (ถนนเมือง) | 0.74 g | 3.73 วิ | 3.87 วิ | 6.1 kN |
| ยาง μ 1.26 อย่างเดียว (Trofeo RS) | 0.88 g | 3.16 | 3.27 | 5.8 kN |
| + พัดลม (= รุ่น Performance, ไม่มีถัง) | 1.59 g | **1.74** | 1.80 | 6.8 kN — **ใกล้สเปกทางการ < 1.6 วิ** (ต่างกันเพราะเราไม่ได้หักเวลา rollout 1 ฟุต) ✔ ยืนยันว่าโมเดลใช้ได้ |
| + พัดลม + หัวพ่น 80 kN (เต็มแรงตามผู้บริหาร) | 5.36 g | 0.52 | 0.53 | 10.9 kN |
| **เป้า: μ 1.1 + พัดลม + หัวพ่น 70.3 kN** | 4.70 g | **0.58** | 0.61 | 11.1 kN |

- ขับล้อหลังอย่างเดียว ยางทำได้แค่ `a = μ·g·0.58 / (1 − μ·h/L)` = **0.76 g** (μ 1.1) เพราะล้อหลังรับน้ำหนักแค่ 58%
- **เพดานหน้าลอย** (ถ้าแรงทั้งหมดมาจากยาง): `a = g·0.42·L/h` = **2.96 g** — เกินนี้หน้ารถยกขึ้น
- หัวพ่นดันที่ความสูง ~0.5 ม. ซึ่งอยู่เหนือ CG ไม่มาก จึง**ไม่ทำให้หน้าเชิด** → ที่ 4.7 g ล้อหน้ายังกดพื้น 11 kN
- หัวพ่นที่ต้องใช้: **70 kN** (μ 1.1 + พัดลม) · 66 kN (μ 1.26 + พัดลม) · 81 kN (ไม่มีพัดลม เกินเพดาน 80 kN = **พัดลมจำเป็นจริง**)
- แบ่งแรง 4.64 g: ยางกับพัดลม ~1.1 g + หัวพ่น ~3.6 g · ใช้แก๊ส 0.59 วิ ≈ **28 หน่วย**

### 5.2 แอ่งน้ำ + hydroplaning + ละอองน้ำ

- แอ่งน้ำ = polygon บนถนน (`puddles` ใน `public/data/`) วางที่ต่ำตามแยก/ริมขอบทาง · 6–10 แอ่งต่อรอบ · ล้อไหนอยู่ในแอ่ง เช็คต่อล้อจาก raycast
- **hydroplaning** (สูตร NASA/Horne V = 9·√psi นอต): ยาง 36 psi → **100 กม./ชม.** · ในเกม: ล้อในแอ่ง + v > 100 → μ ล้อนั้น ×0.35 · ล้อหน้าเหินน้ำ = เลี้ยวเบาลง (understeer) · ล้อหลังเหินน้ำด้านเดียว = ท้ายส่าย yaw ±0.3 rad/s สุ่มตาม seed · เสียงยางเงียบลง + พวงมาลัยไม่หนืด
- ช้ากว่า 100 ในแอ่ง: μ ×0.75 + ความเร็วหายเพิ่ม `0.002·v²` (แรงต้านน้ำ) + น้ำกระจายใหญ่
- **ละอองน้ำจากล้อ:** อัตราอนุภาค `∝ v·ความลึก` · ใช้ instanced quad เดียว 1 draw call · สูงสุด 400 อนุภาค (medium) / 150 (low) · ความเร็วพุ่ง = ความเร็วผิวยาง (v) ไปด้านหลังและเฉียงขึ้น 15° · อายุ 0.6 วิ · ตอน boost ไอพ่น 4 ลำตีละอองให้ฟุ้งเป็นม่านกว้าง ×2

### 5.3 สายไฟ — catenary + Verlet (เชิงเส้น)

**ทำไมไม่ใช้ Verlet ที่บังคับความยาวเส้นตรง ๆ:** ลองแล้วในสคริปต์ สายยาว 35 ม. หย่อน 0.9 ม. มีแรงตึง ~1,000 N เทียบน้ำหนักต่อปล้องแค่ 17 N · ทำ 2–10 รอบต่อเฟรม สายยังหย่อนเกินจริง 66–156% (ยืดเหมือนยาง) · ถ้าทำให้ตรงต้องใช้หลายสิบรอบต่อเฟรม ซึ่งเกินงบมือถือ

**โมเดลที่ใช้:**
```
ตำแหน่งจุด i = รูปทรง catenary พัก (คำนวณล่วงหน้าตอนโหลด: หย่อนตรงสูตร 100%) + การเคลื่อนตัว d_i (y ขึ้น, z ด้านข้าง)

```

## 10. สิ่งที่ยังไม่ยืนยัน (มีผลกับตัวเลข)

- ความกว้างถนนจาก Street View ±2 ม. → R โค้ง 90° เปลี่ยน ~3.4 ม. ต่อ 1 ม. (ความเร็ว ±3–4 กม./ชม.)
- ขนาดแยก 224 (40×50 ม.) และตำแหน่งมุมสวนซุ้มประตู ได้จากภาพ + OSM → **R 56 ม. ควรเช็คกับภาพดาวเทียม** (ถ้าช่องเกาะกลางแคบกว่า 27 ม. R ลดลง)
- ผิวน้ำในคูต่ำกว่าถนนเท่าไร · ระยะโคมริมคูตรงจุดกระโดด
- น้ำหนักรถ (~1,700 ยังไม่ final) · ฐานล้อ 2.82 · CG 0.40 · สัดส่วนน้ำหนัก 58% หลัง → เพดานหน้าลอย 2.96 g ขึ้นกับค่าเหล่านี้
- แรงหัวพ่น 80 kN vs พ่นได้ 5–6 วิ ขัดกันในข่าว — ไฟล์นี้ใช้ impulse 146 kN·s เป็นตัวตั้ง (คำนวณจากถังจริง)
